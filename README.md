# dsh-plugin-catalog

给 DeepSeek Harness 装一个「插件清单」：左边多一个面板，能看清每个插件**是什么、怎么用、装没装成、被调用过多少次**，顺手还能**更新、卸载、导出一份手册**。

两处入口：

| 入口 | 位置 | 适合 |
| --- | --- | --- |
| 侧栏面板「插件清单」 | 左侧边栏图标（`sidebar.panellist` 席位） | 想看、想点、想改 |
| 工具 `plugin_catalog` | 模型工具（可以直接问） | 让模型自己查、自己改 |

## 装之前要知道

- 包声明了 `dsh.bundle`（`cordis.patch.yml`），所以 `dsh plugin add <目录或仓库>` 能装；装完**重启 DSH** 才会加载宿主代码。
- 面板部分（`client.js`）走 `dsh.client`，宿主部分（`index.js`）提供工具与 HTTP 路由。
- 没有安装任何依赖，`docx.js` 是自带的最小 OOXML 写入器。

## 新装的插件会自动补用法

面板对**没有精编说明**的插件会现场起草「作用 + 怎么用」：斜杠命令 → 工具（`tools.register({ name })` 与 `defineTool({ name: X_TOOL_NAME })` + `const X_TOOL_NAME = '...'` 都认）→ 界面类插件（只有 `dsh.client`）→ README 的用法/功能小节 → 描述，标「（自动起草，可润色）」。作用优先取包内 `locale/zh.json`；只写了英文描述时，用中文 README（`README.zh-CN.md` 等）的第一段正文补一句中文。

所以刚下载的插件不用等任何重建：打开面板就能看到它做什么、从哪进；面板在 DSH 重新变为可见时会自动重读清单。要进 Word 手册与导出文件，则等下一次定时同步（每 2 小时）或手动跑 `sync_catalog.py`——`auto: true` 的条目会跟着包刷新。

导出与手册里的文案由 `插件清单-生成脚本/sync_catalog.py` 用同一套规则写进 `plugin_catalog.json`（`auto: true` 的条目随包刷新）。

## 面板里有什么

- **搜索**：空格切词，多个词要同时命中（`ops bash` 能找到 dsh-ops，因为它挂载的工具叫 `ops_bash`）。搜索范围包括插件名、作用、怎么用、大类、挂载项、README 节选、被调用的工具名、版本号。
- **排序**：按大类 / 名称（默认）、按使用次数、按最近调用。
- **分类筛选** + **只看可更新**。
- **每张卡片**：标题、版本、包名（与标题不同时）、作用、怎么用、挂载项、使用次数与占比。
- **点开卡片**：挂载项明细、README 用法节选、功能重叠提示、最近一次调用、被调用的工具、「复制包名」（拿去「设置 → 插件」里搜）。
- **更新 / 一键更新**：先弹确认条（从哪版到哪版、会先卸载再装、失败会回滚），确认后执行；多个插件串行跑。
- **卸载**：只有宿主说这个包可以移除时才出现按钮；确认条会写明**没有撤销按钮**，删掉要重新安装。
- **一键导出到桌面**：选 Word 或 PDF，直接写到桌面；**选 PDF 就只得到 PDF**（中间的 Word 写在系统临时目录，转完删除），结果条给出完整路径、大小、页数与「下载一份」。
- **出错了不会白屏**：面板包了一层错误边界，渲染异常时显示原因和「重试渲染」。

- **点开卡片**还有三样东西：「开关：」（当前启用/停用 + 一键切换，包文件不动）、「安装来源：」（profile 里的依赖写法，git 与本地目录会说明不会自动更新）、「版本历史：」（npm 上全部已发布版本，可一键装回旧版本）。
- **不打开面板也能用**：对话里输入 `/plugin-catalog`（可带包名、`updates` 或大类名）；或者直接访问 `GET /dsh-plugin-catalog/page`，得到一整页可打印的清单。

## 工具 `plugin_catalog`

| action | 作用 |
| --- | --- |
| `list` | 列出全部插件（可筛大类） |
| `categories` | 八个大类与各自数量 |
| `search` | 关键词搜（与面板同一套字段） |
| `get` | 单个插件的完整信息 |
| `usage` | 使用统计排行 + 口径说明 |
| `updates` | 对比 npm registry 的最新版本（缓存 6 小时，`force` 跳缓存） |
| `update` | 更新一个插件（要 `confirm: true`） |
| `remove` | 卸载一个插件（要 `confirm: true`） |
\1
| `versions` | 一个包的版本历史（挑旧版本回退用） |
| `enable` / `disable` | 启用/停用插件（只改 profile 的选择，不删包） |

## 数据从哪来

1. **profile 的 `package.json`**：`dsh.profile.bundles` + `dependencies` 的精确版本 → 谁被声明了、装的什么版本。
2. **各包的 `package.json` 与 `locale/*.json`**：显示名、简介、图标。
3. **各包的 `cordis.patch.yml`**：这个 bundle 实际挂载了什么（`- id:` / `name:` 行）。
4. **各包的 README**：`README.zh-CN.md` → `README_ZH.md` → `README.md`，截取「用法 / 使用 / Usage / 快速开始」小节。
5. **会话日志**（`$DSH_HOME/sessions/**/session*.jsonl.zstd`）：`tool/call` 事件 → 使用次数。

人工维护的那张「工具 → 包」归属表在 `../../插件清单-生成脚本/tool_owners.json`（本仓库里的 `catalog.js` 是它生成出来的，别手改）。

## 写操作与安全边界

- 更新、卸载都**转发给宿主 `pluginManager`**（`updateBundle` / `removeBundle`），插件自己不写一套安装器，所以宿主的备份、回滚、profile manifest 与在跑 agent 的处理逻辑都仍然生效。
- 写路由只接受**本机回环地址**，并要求请求体里有 `confirm: true`；同一时刻只允许一个写操作在跑。
- 更新后多半要**重启 DSH** 才生效（宿主返回 `restart-required` 时面板会明说）。
- 本插件**不卸载自己**（那会连带删掉面板和工具）。
- 导出只写桌面（或显式指定的目录），下载接口只肯发桌面与旧的 `~/.dsh/exports/plugin-catalog/` 里的 `.docx` / `.pdf`。

## 使用统计的口径

- 只数**工具调用**：不含斜杠命令、不含技能调用、不含面板里的点击。
- 归属靠人工映射表：能确定归属的才算到插件头上，确定不了的记「未归属」，**不摊给任何插件**。
- 数字是本机会话日志的累计；换机器或清掉会话会归零。缓存 10 分钟。

## 已知限制

- 更新检查只认 **npm registry 的最新版**：`github:owner/repo#commit` 与 `link:` 本地目录的包显示「无发布源」，本插件不判断它们的更新。
- 卸载**不可撤销**（宿主没有提供撤销入口）。
- 面板配色依赖 DSH 的 `--dsw-alias-*` 主题变量，DSH 若改名，样式会退化。
- 面板入口依赖 `sidebar.panellist` 席位，这个席位不是公开稳定 API。

## 维护

- 插件的「人话描述」在 `../../插件清单-生成脚本/plugin_catalog.json`（唯一数据源），改完跑 `sync_catalog.py --force` 会重建 `catalog.js`、`client.js` 与手册。
- `sync_catalog.py --check` 只报告版本漂移，不写盘。
